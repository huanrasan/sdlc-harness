# 0001. Use AGENTS.md and Agent Skills as the agent-agnostic core

**Status:** Accepted
**Date:** 2026-09-16
**Deciders:** maintainers

## Context and problem
The harness must work with any coding agent (Claude Code, Codex, Copilot, Cursor, Gemini CLI, Windsurf, OpenCode and
future ones). Each agent has its own instruction file and extension mechanism.

## Decision drivers
Portability (high), vendor neutrality (high), context efficiency (high), maintenance cost (medium).

## Options considered
1. Per-agent native configuration maintained in parallel.
2. Canonical `AGENTS.md` + `.agents/skills/` (Agent Skills spec) with generated thin adapters.
3. A custom agent runtime/plugin framework that wraps models.

## Decision
Option 2. Both standards are open and stewarded neutrally (AGENTS.md under the Agentic AI Foundation; Agent Skills as
an open specification), widely adopted, and support progressive disclosure. Adapters are declared in
`.harness/adapters.toml` and generated by `sdlc sync`.

## Consequences
- Positive: one source of truth; new agents need a data entry, not code.
- Negative: discovery paths evolve; the adapter catalog needs periodic review. Agents without skill support rely on the
  skills index table in AGENTS.md and read `SKILL.md` files on demand.
- Option 3 was rejected: it would force teams to abandon the agents they already use.

## Revisit triggers
A major agent drops AGENTS.md or Agent Skills support, or a successor standard is adopted by the AAIF.
